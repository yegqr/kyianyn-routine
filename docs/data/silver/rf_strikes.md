# rf_strikes: удари по Росії і запуски по Україні (silver)

Дві таблиці з модуля `src/airalerts/silver/rf_strikes.py`, джерело одне: відкрите API dronestrikemap.com. Рішення користувача 2026-10-11: замінити попередню версію (Telegram МО РФ, Собянін, Росавіація, Генштаб і оцінки Jev), бо і дані, і міра були слабкі. Стара версія є в історії git; її bronze лишився в `data/bronze/telegram/` і `data/bronze/strikes_rf/ukwiki_list_2026/`, її таблиці і кеш Jev видалено 2026-10-11, денні суми МО РФ збережено в `data/verification/mod_russia_daily_drones.csv`.

## Що це

- `strike_points`: рядок = одна точка удару за день: країна (`RU` удари по Росії, `UA` по Україні), місце, регіон, короткий опис цілі, зброя, достовірність, статті-джерела.
- `strike_days`: рядок = (день, країна): скільки дронів і ракет запущено (діапазон min..max) і збито. Для `RU` це брифінги МО РФ, для `UA` Повітряні сили.

## Bronze

Кожен запуск це новий знімок, нічого не перезаписується: історії змін сайт не має, тож лише знімки кажуть, що він показував у певний момент. У знімку відповіді `/api/meta`, `/api/strikes`, `/api/timeline`, `/api/events`, `/api/sources`, `/api/day/<d>` для кожного дня від 2026-04-16 і `fetch_log.jsonl` (URL, статус, байти, sha256, час). Модуль бере найновіший знімок і падає, якщо в журналі є відповідь не 200.

Знімок 20261011T083437Z: 184 запити, усі HTTP 200, останній о 2026-10-11T08:38:54Z; 179 файлів днів (2026-04-16..2026-10-11); 8735 точок у `/api/strikes` з 2024-07-30.

Сайт збирає новини з 51 джерела (RSS медіа, Telegram офіційних органів, МО РФ, ISW) і сам зводить їх у точки і підсумки дня. Хто і як це робить, на сайті не описано; описи цілей схожі на автоматичні.

## Колонки

`strike_points`:

| колонка | тип | опис |
|---|---|---|
| `date` | DATE | день за UTC (див. Час доступності) |
| `country` | VARCHAR | `RU` або `UA` |
| `place`, `region` | VARCHAR | місце і регіон англійською, як на сайті |
| `occupied` | BOOLEAN | регіон має позначку `(occupied)`: окупована територія України, яку сайт записує до `RU` |
| `lat`, `lon` | DOUBLE | координати; для 297 точок `RU` у таблиці це центр області («reported for the whole oblast») |
| `summary` | VARCHAR | опис цілі («refinery, power grid», далі «impact reported» через крапку посередині) |
| `confidence` | VARCHAR | `confirmed`, `reported`, `claimed` |
| `weapons` | VARCHAR[] | `drone`, `missile` або порожньо |
| `n_articles`, `article_sources` | INTEGER, VARCHAR[] | скільки статей і з яких джерел |
| `is_energy` | BOOLEAN | `summary` має `refinery`, `fuel depot`, `oil`, `power grid`, `power plant`, `substation`, `gas facility` або `energy` |
| `is_moscow` | BOOLEAN | регіон `Moscow` або `Moscow Oblast` |
| `available_at` | TIMESTAMP | `date` 00:00 UTC + 30 год |

`strike_days`: `date`, `country`, `launched_min`, `launched_max`, `intercepted`, `estimated` (сайт позначив оцінку), `drones_max`, `drones_intercepted`, `missiles_max`, `missiles_intercepted`, `basis` (перелік джерел підсумку), `available_at` (як вище).

Метадані Parquet обох таблиць: `snapshot`, `fetched_at`, `lag_hours`.

## Час доступності

На сайті є лише дата, немає години, часу публікації і історії змін. День сайту збігається з днем публікації звітів МО РФ: денна сума збитих дронів над Росією дорівнює сумі звітів МО РФ, опублікованих того ж дня, у 72 з 101 дня і відрізняється не більше ніж на 10% у 85 (`checks`, рядок нижче). Звіти МО виходять близько 05:30Z і 18:00Z, тож день UTC і день за Києвом дають ту саму звірку і їх не розрізнити. В обох випадках день d закінчується не пізніше d + 1 день 00:00Z. Рішення користувача 2026-10-11: день d відомий з d + 1 день + 6 год, `available_at = d 00:00Z + 30 год`. День, який на момент знімка ще не відомий, у таблицю не йде (2026-10-11 відкинуто). `ASOF`: `SELECT * FROM <таблиця> WHERE available_at < {t}`.

Залишковий ризик витоку: сайт міг дописати чи виправити старий день пізніше, а знімок бачить лише останній стан. Наступні знімки дадуть змогу це виміряти.

## Ознаки для gold

`features(con, t_table)`: рядок на кожен `t_utc`, лише рядки з `available_at < t_utc`. «День» = найновіший відомий день (`available_at` у `[t - 24 год, t)`), «три дні» = `[t - 72 год, t)`. Точки Росії беруться без окупованих територій України (`country = 'RU' AND NOT occupied`).

| колонка | тип | визначення |
|---|---|---|
| `rf_points_1d`, `rf_points_3d` | INTEGER | точок ударів по Росії за день і за три дні |
| `rf_regions_3d` | INTEGER | різних регіонів серед точок трьох днів |
| `rf_energy_1d`, `rf_energy_3d` | INTEGER | точок з `is_energy` |
| `rf_moscow_3d` | INTEGER | 1, якщо за три дні є точка з `is_moscow` |
| `rf_drones_intercepted_1d` | INTEGER | `intercepted` дня для `RU` (заява МО РФ) |
| `ua_missiles_launched_1d`, `ua_drones_launched_1d` | INTEGER | `missiles_max`, `drones_max` дня для `UA` |
| `hours_since_rf_energy` | DOUBLE | годин від `available_at` останньої точки енергетики до t, не більше 336 |

`features()` відхиляє t пізніше за `data_end()` = час знімка, округлений вниз до години (`ValueError`).

## Пастки

- Ознаки описують учорашній або позавчорашній день, а не останні години: так задано затримкою 30 год.
- `rf_moscow_3d` майже завжди 1 (середнє 0.87): сама по собі мало розрізняє.
- Опис цілі автоматичний і буває хибний (точка «Moscow» з текстом про удари Росії по заводах дронів у Європі, 2026-04-17). `is_energy` це regex по цьому опису.
- Окуповані території сайт пише під `RU`; ознаки їх відкидають (283 точки). Окупований Крим МО РФ теж рахує у своїх збитих дронах, тож `rf_drones_intercepted_1d` їх включає.
- `launched_min` і `launched_max` різняться, коли джерела дають різні числа; ознаки беруть верх.
