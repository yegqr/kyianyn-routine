## 0. Загальні правила

- **Період:** від T0 = 2026-05-01 00:00 за Києвом = `2026-04-30T21:00:00Z` до дати зрізу.
- **Старт забору:** `FETCH_FROM = 2026-04-16T21:00:00Z` (T0 мінус 14 діб, рішення користувача 2026-10-10), щоб ознаки з вікном назад до 14 діб були повні вже 1 травня. Погода, астрономія, календар і Kremlin назад не дивляться, тому їх не розширюємо. Сторінки Вікіпедії беремо цілком.
- **Час:** усі мітки часу в UTC, формат `2026-10-10T12:42:56Z`. Київський час рахує лише обробка: до 2026-10-25 це UTC+3, далі UTC+2.
- **Час доступності:** кожен запис має момент, коли він став публічним (`published_at`, `announced_at` або `available_at_utc`). Ознака для прогнозу в момент t бере лише записи з часом доступності < t. Запис без такого часу йде лише в мітку.
- **Лише дописуємо:** у `data/bronze/` старий рядок не змінюємо і не видаляємо, похідні таблиці пишемо в `data/silver/`. Повторний запуск докачує лише нове, перерваний бекфіл продовжує з місця обриву. Після кожного запуску рядок у `data/bronze/MANIFEST.md`: джерело, час запуску (UTC), записів, перший і останній час.
- **Ввічливо і без ключів:** один потік на джерело, пауза 1-2 с, повтор із паузою на HTTP 429 і 5xx. Токени, реєстрації і нові залежності лише з «так» користувача. Код лише на stdlib Python 3.11+. Завантажене не виконуємо, скрипти запускаємо як `python3 -I`.

**Порядок роботи:** (1) Telegram, потоки A, B, C з 0.1, у фоні; (2) погода, розділ 3; (3) астрономія, розділ 4; (4) `dates.csv`, розділ 5; (5) Kremlin і Вікіпедія, розділ 6; (6) dronestrikemap, розділ 8; (7) перевірки з кожного розділу і маніфест.

### 0.1 Telegram: спільний рецепт

Усі 17 каналів з розділів 1, 2, 6, 7 і 8 забираються одним скриптом; канал, потрібний кільком розділам, качаємо один раз. Ендпоінти (без логіну): `https://t.me/s/<channel>` дає до 20 найновіших постів, `?before=<id>` до 20 постів з меншим id. Пошук `?q=<слово>` віддає лише ~20 найновіших збігів і для архіву не годиться.

| Поле поста | Де в HTML |
|---|---|
| межа поста | `<div class="tgme_widget_message_wrap` |
| канал і id | `data-post="<channel>/<id>"` |
| час | `<a class="tgme_widget_message_date" ...><time datetime="2026-10-10T12:42:56+00:00">`, UTC |
| текст | `<div class="tgme_widget_message_text js-message_text">`; цитата у відповіді має клас `js-message_reply_text`, її не брати |
| перегляди | `<span class="tgme_widget_message_views">55.5K</span>` |
| правка | `<span class="tgme_widget_message_meta">edited &nbsp;<a ...>` |
| репост | `<a class="tgme_widget_message_forwarded_from_name" href="https://t.me/vitaliy_klitschko/7821">` |

**Сирий формат:** `data/bronze/telegram/<channel>.jsonl`, один JSON на пост, `<channel>` точно як у `data-post`. Рядки не відсортовані: читати, прибирати дублі за `post_id` (лишати перший рядок) і сортувати.

| Поле | Тип | Опис |
|---|---|---|
| `channel` | str | канал без @ |
| `post_id` | int | id поста |
| `published_at` | str | час публікації, UTC з `Z` |
| `text` | str | текст без HTML, `<br>` стає `\n`, емодзі лишаються; `""` для поста лише з медіа |
| `edited` | bool | пост змінено після публікації |
| `views` | str або null | перегляди як на сторінці («6.83K») |
| `forwarded_from` | str або null | джерело репосту: `<channel>/<id>` або ім'я автора |
| `url` | str | `https://t.me/<channel>/<id>` |
| `fetched_at` | str | час забору, UTC з `Z` |

**Скрипт** [scripts/bronze/tg_fetch.py](../scripts/bronze/tg_fetch.py) (stdlib; `get()` і `parse()` можна імпортувати): `python3 -I scripts/bronze/tg_fetch.py <channel> data/bronze/telegram/<channel>.jsonl` (since за замовчуванням FETCH_FROM, пауза 1.5 с). Друкує підсумок: сторінки, рядки, перший і останній час, min і max id. Перший запуск іде від найновішого поста назад до since, наступні дописують лише новіше і добудовують перерваний бекфіл без дублів. Довгий канал можна качати частинами (`before stop_id`, див. docstring) і зливати: `python3 -I scripts/bronze/tg_fetch.py merge <out.jsonl> <part.jsonl>...`. У відповіді береться власний текст поста, а не цитата (OP_UA/18640); неіснуючий канал дає вихід з помилкою без файлу.

**Пастки (усі канали):**
- Сторінка буває коротша за 20 постів (5-9 у КМВА, Кличка, Собяніна): альбоми і видалені пости. Дірка в id не означає втрату; зупинка лише за датою.
- t.me/s показує тільки останню версію відредагованого поста, часу правки немає. Для ознак текст постів з `edited=true` ненадійний (доповнення могли з'явитися пізніше); для мітки це не витік.
- Репости: КМВА репостить Кличка, Зеленського, ДСНС, ДТЕК, @AerisRimor репостить @kpszsu. Для правил на кшталт «2 незалежні канали» брати лише пости з `forwarded_from = null`.
- Неіснуючий або закритий канал віддає HTTP 200 і 0 постів. 0 постів на відомому каналі означає, що змінилась розмітка: зупинитись і повідомити.
- Офіційних лімітів немає: понад 1500 запитів з паузою 1.2-1.5 с пройшли без 429; @kpszsu повільніший, ~8 с на сторінку. Умови використання Telegram щодо t.me/s не перевіряли; Telegram API потребує реєстрації (лише з «так»).

**Черга бекфілу.** [scripts/bronze/tg_backfill.sh](../scripts/bronze/tg_backfill.sh) `A|B|C` качає канали потоку один за одним; три потоки йдуть паралельно (якщо пішли 429, зменшити до одного). Лог `data/bronze/telegram/logs/<потік>.log`: рядок `done <канал>` або `FAIL <канал>`. Разом ~9 тис. сторінок з паузою ~4.5 с на сторінку; найбільший канал @kyiv_airdef. ## 1. Тривоги (м. Київ)

**Що збираємо:** усі пости КМВА @VA_Kyiv (https://t.me/s/VA_Kyiv) з FETCH_FROM; з них обробка будує інтервали тривог по місту: старт, відбій, рівень (жовтий або червоний з вересня 2026). Латка: eTryvoga @UkraineAlarmSignal (https://t.me/s/UkraineAlarmSignal), лише старт для рідкісного відбою КМВА без старту.

**Чому КМВА.** Порівняння 2026-10-10 (збіг = старт у межах 5 хв): за 05-01..09-05 VA_Kyiv збігається з official CSV у 270 з 274 тривог (лише у VA 49, лише в official 4); volunteer CSV на 10-07..10-09 пропускає 17 з 25 тривог VA. Відкинуто:
- CSV Vadimkin volunteer: зайві naive-тривоги, з вересня 2026 пропускає більшість жовтих;
- CSV Vadimkin official: закінчується 2026-09-07, з 2026-08-29 05:29Z до 2026-09-02 13:48Z немає жодного рядка по всіх регіонах;
- alerts.in.ua: історія лише з токеном;
- eTryvoga як основне: ~1000 постів на добу, весь період ~8000 сторінок.

**Як забирати:** VA_Kyiv: рецепт 0.1. eTryvoga весь не качати: `python3 -I scripts/bronze/etryvoga_patch.py [годин до відбою, типово 3]` бере відбої без старту з `va_count.py`, бісекцією по `?before=<id>` знаходить сторінку з часом відбою, читає сторінки назад до відбою мінус 3 год і дописує пости (формат 0.1) у `data/bronze/telegram/UkraineAlarmSignal.jsonl`; повторний запуск дописує лише відсутнє. Файли: `data/bronze/telegram/VA_Kyiv.jsonl`, `data/bronze/telegram/UkraineAlarmSignal.jsonl`.

**Правила обробки** (склеювання в тривоги і рішення про відбій без старту: [kyiv_alerts.md](data/silver/kyiv_alerts.md)):
- head = текст без початкових емодзі і знаків, перші 120 символів: `re.sub(r"^[^0-9A-Za-zА-Яа-яЄєІіЇїҐґ]+", "", text).strip()[:120]`.
- Відбій: `^(м\.\s*Київ\s*[-–]\s*)?[Вв]ідбій`.
- Старт: `^((м\.\s*Київ\s*[-–]\s*)?[Пп]овітряна тривога|(Червоний|Жовтий) рівень небезпеки|(У Києві |У столиці )?[Оо]голошено повітряну тривогу)`; рівень red, якщо в head є «Червоний», yellow, якщо «Жовтий», інакше alert. Нагадування всередині тривоги («У Києві лунає повітряна тривога...», «Сили ППО працюють...», «Загроза БпЛА триває...») не старт: regex з `^` їх відсікає.
- Формати КМВА: старий («🔴 м. Київ - повітряна тривога!», «🟢 м. Київ - відбій повітряної тривоги!») від 17868 (2026-05-02T06:50:58Z) до 20895 (2026-09-23T02:06:17Z); новий («🟡 Жовтий рівень небезпеки», «🔴 Червоний рівень небезпеки», «🟢 Відбій повітряної тривоги.») з 20477 (2026-09-08T08:02:54Z). З 09-08 до 09-23 формати змішані.
- Латка eTryvoga, лише м. Київ: одиночний пост, де перший рядок без емодзі рівно «Київ», а другий «Червоний рівень тривоги», «Жовтий рівень тривоги» або «Повітряна тривога»; або груповий пост з рядком рівно «• Київ» під заголовком «🔴 Червоний рівень тривоги» чи «🟡 Жовтий рівень тривоги». Не старт: «🚀 Київ / Загроза...» (651294), «⚠️ Київ / ЗМІ повідомляють про вибухи» (651298), «🟡 Відбій червоної тривоги» (це зниження до жовтого). «Троєщина (Київ)» це район, «(Київська обл.)» область. Брати останній старт м. Київ перед відбоєм.

**Витік:** старт = `published_at` поста старту, кінець = `published_at` відбою. На момент t відкрита тривога має лише старт. КМВА публікує в середньому на 4-5 с пізніше за офіційний канал.

**Пастки:**
- Відбій без старту за період один: VA 21659 (відбій 2026-10-10T11:35:57Z); старт є в eTryvoga о 10:57:27Z («🔴 Червоний рівень тривоги», «• Київ»), його бере латка.

- Червоний на жовтий: КМВА пише відбій і за хвилину новий жовтий старт (2026-10-07 20:48Z і 20:49Z), у даних це дві тривоги.

**Перевірка:** `python3 -I scripts/bronze/va_count.py data/bronze/telegram/VA_Kyiv.jsonl` ([va_count.py](../scripts/bronze/va_count.py)) має дати `alerts by Kyiv month: {'05': 58, '06': 45, '07': 59, '08': 120, '09': 185, '10': 78} total 545 orphan ends: [21659]`.

## 2. Мітка ракетного удару

**Що збираємо:** усі пости 7 каналів. Моніторингові, що в реальному часі ведуть Київ (загроза, рух ракет і дронів, вибухи, ППО, уламки, влучання, відбій): @truexakyiv (найшвидші пости про вибухи і влучання по районах), @war_monitor (загальноукраїнський: тип ракет, «Вибухи в Києві», відбій загрози балістики), @AerisRimor (треки ракет і дронів на Київ, «Пролунали вибухи»), @kyiv_nebo («Балістика на Київ», треки, відбій; контекст), @kyiv_airdef (треки по районах і передмістях, «БАЛІСТИКА НА КИЇВ»; контекст). Офіційні, як підтвердження: @VA_Kyiv (рівні небезпеки, червоний = ракети, уламки, влучання по районах) і @vitaliy_klitschko («Вибухи в столиці», влучання, постраждалі). Парсер зберігає все сире; мітку «ракетний удар по Києву в годину h» будує обробка: [kyiv_threat_hourly.md](data/silver/kyiv_threat_hourly.md), [JEV.md](JEV.md). Забір: рецепт 0.1.

Запасні (живі 2026-10-10, не качаємо): @kievreal1 (глибину архіву не перевіряли), @monitoring_kyiv, @kyivalarm, @kyivcityofficial (дублює КМВА і Кличка), @dsns_kyiv (наслідки і пожежі). Відкинуті: @kyiv_alarm (43 підписники), @kyiv_tryvoga, @kyiv_monitoring, @kyivoperativ (мовчать з 2024-2025), @chyste_nebo (0 постів у t.me/s).

**Правила обробки.** Словник класів, міста і області (Python `re`, `re.I`, укр. і рос.): [`src/airalerts/silver/telegram_rx.py`](../src/airalerts/silver/telegram_rx.py) (`CLASSES`, `KYIV_CITY`, `OBLAST`, `KYIV_ONLY`, `classify`). Правило години, яке діє: [kyiv_threat_hourly.md](data/silver/kyiv_threat_hourly.md). Прості правила A і B лишились як база для порівняння з міткою: година h, якщо в [h, h+1) є (A) пост КМВА або Кличка з класом explosion, debris або impact_damage, або (B) щонайменше 2 різні моніторингові канали з таким постом по місту в межах 30 хв; в обох випадках за 90 хв до поста є пост з missile_threat у будь-якому з 7 каналів. Репост не рахується окремим джерелом.

**Витік:** для ознак стандартно `published_at < t`. Для мітки час події = `published_at` першого поста-доказу, а не ранкового зведення.

**Пастки:**
- Київські канали майже не пишуть слово «Київ» (на останніх 20 постах @kyiv_airdef і @AerisRimor 0 з 20; пишуть райони, «На Білогородку»). Місто визначати за районами і каналом, передмістя відсікати списком `OBLAST`.
- «Вибухи» бувають від дронів і від роботи ППО; без ракетного контексту це не ракетний удар. Ранкове зведення КМВА («атакував столицю балістичними ракетами») приходить через години: лише для типу зброї.

## 3. Погода

**Що збираємо:** погодинний прогноз ECMWF IFS HRES 9 км для центру Києва (50.4501, 30.5234): хмарність, опади, вітер (швидкість, пориви, напрям), видимість. Кожен прогін (00, 06, 12, 18 UTC) зберігаємо цілим із часом старту, тож для моменту t беремо лише прогноз, виданий до t.

**Джерело:** Open-Meteo Single Runs API, `models=ecmwf_ifs`, https://single-runs-api.open-meteo.com/v1/forecast. Без ключа; безкоштовно лише для некомерційного використання (для шкільного проєкту підходить, для комерційного потрібен платний план); дані CC BY 4.0. Архів ECMWF IFS HRES з березня 2024. Відкинуто (перевірено 2026-10-10):
- Previous Runs API для `ecmwf_ifs`: немає поривів і видимості (0 з 3912 год); видимість там є лише в `ukmo_seamless` і з дірками;
- `best_match`, `gfs_seamless`, `icon_seamless`, `gem_seamless`: без видимості;
- Historical Forecast API: немає часу видачі прогнозу, тобто ризик витоку;
- OGIMET SYNOP 33345: спостереження раз на 3 год і без часу публікації.

**Як забирати:**
- Один запит = один прогін, 168 погодинних значень від `run`: `https://single-runs-api.open-meteo.com/v1/forecast?latitude=50.4501&longitude=30.5234&hourly=cloud_cover,precipitation,wind_speed_10m,wind_gusts_10m,wind_direction_10m,visibility&models=ecmwf_ifs&run=2026-10-09T12:00&timezone=UTC&format=json`.
- Прогони кожні 6 год від `2026-04-23T00:00` до останнього опублікованого. Останній: `https://api.open-meteo.com/data/ecmwf_ifs/static/meta.json`, поля `last_run_initialisation_time` і `last_run_availability_time` (unix-секунди); прогін 06:00 2026-10-10 вийшов о 12:22:53 UTC, через 6.4 год.
- Неопублікований або відсутній прогін дає HTTP 400 `{"reason":"The requested model run is not available. ...","error":true}`: пропустити і повторити пізніше. Ліміти: до 10 000 викликів на добу, 5 000 на годину, 600 на хвилину.
- Код: [scripts/bronze/wx_fetch_run.py](../scripts/bronze/wx_fetch_run.py) `python3 -I scripts/bronze/wx_fetch_run.py data/bronze/weather 2026-10-09T12:00 2026-10-10T06:00`. Бекфіл усіх прогонів: [scripts/bronze/wx_backfill.py](../scripts/bronze/wx_backfill.py) `[--out DIR] [--from 2026-04-23T00:00] [--to RUN] [--dry-run]`; відновлюваний, прогін з HTTP 400 пише в `ecmwf_ifs_missing_runs.csv` і питає знову, лише поки прогону менше 48 год.

**Сирий формат і куди:**
- `data/bronze/weather/openmeteo_single_runs/ecmwf_ifs_<YYYYMMDDTHH>.json`: відповідь як є, файл на прогін.
- `data/bronze/weather/ecmwf_ifs_runs.csv`: рядок на пару (прогін, година), колонки `run_utc, valid_utc, lead_h, cloud_cover_pct, precipitation_mm, wind_speed_10m_kmh, wind_gusts_10m_kmh, wind_direction_10m_deg, visibility_m, available_at_utc, fetched_at_utc`. Порожня клітинка = null.
- Одиниці: % , мм (сума за попередню годину), км/год, градуси, м. Приклад (прогін 2026-10-09T12:00, година 2026-10-10T12:00): хмарність 81, опади 0.0, вітер 12.6, пориви 31.7, напрям 227, видимість 45720.

**Правила обробки:**
- Лише `models=ecmwf_ifs` і `timezone=UTC`, координати не міняти. Вузол сітки 50.439365, 30.476192, ~3.6 км на захід від центру. Якщо `hourly_units` змінилися, зупинитися.
- Ключ (`run_utc`, `valid_utc`); дублікати від повторного запуску прибрати.
- На `lead_h = 0` опади і пориви порожні. Звичайно прогони 06 і 18 UTC мають 145 непорожніх годин з 168, прогони 00 і 12 UTC усі 168; 6 з 681 прогонів коротші з вини джерела (таблиця в [weather_runs.md](data/silver/weather_runs.md), розділ Пастки).
- Для моменту t брати найсвіжіший прогін з `available_at_utc < t`; порожнє значення брати зі старшого прогону.

**Витік:** `available_at_utc = run_utc + 8 год` (фактична затримка 6.4 год плюс запас). З правилом `< t` випередження прогнозу 9-14 год, до 20 год у 6 годинах після пропущеного прогону 2026-06-10T12:00. `fetched_at_utc` не час доступності: бекфіл забирає все сьогодні.

**Пастки:** прогону 2026-06-10T12:00 в архіві нема (HTTP 400). Після вибору прогону частина значень порожня, її закриває старший прогін. Це вузол моделі, не станція; видимість модельна (80..55 200 м у всіх прогонах). Вітер у км/год, не м/с.

**Перевірка:** скрипт на прогонах 2026-10-09T12:00 і 2026-10-10T06:00 дає 336 рядків, непорожніх хмарності і видимості по 313, рядок години 2026-10-10T12:00 як у прикладі. Повний бекфіл (2026-04-23T00:00..2026-10-10T06:00) дає 681 файл і 114 408 рядків CSV = 168 x 681; прогін 2026-06-10T12:00 лише в `ecmwf_ifs_missing_runs.csv`. Решта перевірок: [weather_runs.md](data/silver/weather_runs.md).

## 4. Астрономія

**Що збираємо:** для Києва (50.4501, 30.5234) погодинно: висота Сонця, темно чи ні (цивільні і навігаційні сутінки), освітленість і фаза Місяця; щодня: схід і захід Сонця, сутінки, тривалість дня і ночі. Рахуємо локально, без мережі.

**Джерело:** власний модуль [scripts/bronze/kyiv_astro.py](../scripts/bronze/kyiv_astro.py) на stdlib: рівняння NOAA Solar Calculator (Meeus) для Сонця, Meeus «Astronomical Algorithms», розділ 48, для фази Місяця. Контроль: MET Norway Sunrise 3.0 (https://api.met.no/weatherapi/sunrise/3.0/) і каталог фаз Espenak (https://astropixels.com/ephemeris/phasescat/phases2001.html). Не бібліотека: skyfield, ephem і astral не встановлені, а нова залежність лише з «так»; skyfield потребує файл ефемерид de421.bsp (16.8 МБ), astral без освітленості Місяця.

**Як:** `python3 -I scripts/bronze/kyiv_astro.py build data/bronze/astro` рахує за замовчуванням 2026-04-23..2026-10-31; інший період: `--from YYYY-MM-DD` і `--to YYYY-MM-DD`.

**Формат** (усі часи UTC з `Z`, `date_kyiv` = місцева дата):
- `data/bronze/astro/kyiv_astro_daily.csv`: `date_kyiv, sunrise_utc, sunset_utc, civil_dawn_utc, civil_dusk_utc, nautical_dawn_utc, nautical_dusk_utc, astro_dawn_utc, astro_dusk_utc, day_length_h, night_civil_h, night_nautical_h, moon_illum_midnight, moon_phase_midnight`.
- `data/bronze/astro/kyiv_astro_hourly.csv`: `hour_utc, sun_alt_deg, dark_civil, dark_nautical, moon_illum, moon_phase`.

**Правила:** схід і захід = центр Сонця на -0.833° (рефракція і радіус), сутінки = -6, -12, -18°. `dark_civil` = висота < -6°, `dark_nautical` < -12°. `moon_phase`: 0 новий Місяць, 0.25 перша чверть, 0.5 повня, 0.75 остання чверть; `moon_illum` = частка освітленого диска. Денні значення Місяця на київську північ наприкінці `date_kyiv`.

**Витік:** немає, усе відомо наперед; з іншими даними з'єднувати за `hour_utc` або `date_kyiv`.

**Пастки:**
- Білі ночі: астрономічна ніч (-18°) у Києві не настає з кінця травня до середини липня. `astro_dawn_utc` порожній у 48 рядках (05-29..07-15), `astro_dusk_utc` у 49 (05-23 і 05-29..07-15); 05-24..05-28 сутінки настають після київської півночі і пишуться на наступну дату. Тому темряву міряємо цивільними і навігаційними сутінками.
- Потрібна tzdata з назвою `Europe/Kyiv` (2022b+). Схід і захід Місяця модуль не рахує.

**Перевірка:** `python3 -I scripts/bronze/kyiv_astro.py day 2026-10-10` друкує:

```python
import datetime as dt
Y = 2026
def nth(n, wd, m):  # n-th weekday (0=Mon..6=Sun) of month m
    f = dt.date(Y, m, 1); return f + dt.timedelta((wd - f.weekday()) % 7 + 7 * (n - 1))
def last(wd, m):  # last weekday of month m (m < 12)
    l = dt.date(Y, m + 1, 1) - dt.timedelta(1); return l - dt.timedelta((l.weekday() - wd) % 7)
def orth_easter(y=Y):  # Meeus: Julian date + 13 days (valid 1900-2099)
    a, b, c = y % 4, y % 7, y % 19; d = (19 * c + 15) % 30; e = (2 * a + 4 * b - d + 34) % 7
    m, r = divmod(d + e + 114, 31); return dt.date(y, m, r + 1) + dt.timedelta(13)
E = orth_easter()
print("easter", E, "trinity", E + dt.timedelta(49), "kyiv_day", last(6, 5), "ru_navy", last(6, 7),
      "ru_pvo", nth(2, 6, 4), "ua_repr", nth(3, 6, 5), "ua_navy", nth(1, 6, 7), "ua_af", nth(1, 6, 8),
      "ru_airfleet", nth(3, 6, 8), "ru_tank", nth(2, 6, 9), "ua_tro", nth(1, 6, 10), "ua_holodomor", nth(4, 5, 11))
```
